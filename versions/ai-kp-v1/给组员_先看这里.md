# 给组员：最新版怎么用

这次把最新实现更新在原来的 **`versions/ai-kp-v1/`** 目录，之前发的链接仍可用。
仓库根目录原始代码保留；旧单书房版本可从 Git 历史提交 `d845b73` 找回。

仍然只有一名玩家、一张固定角色卡、一个 AI 主持。
这次把原创书房故事延伸成“旧书房 → 车站 → 档案室”三个地点，
能带着线索和物品继续，也能回到已经去过的地方。

现在是 **3 个地点、8 条线索、4 种物品、17 个规则主题**。
v2 目前 98 项离线测试全部通过，此前也用真实 DeepSeek 检查了自由表达和少量完整回合。
但这还不等于有人从头到尾随机跑完全部剧情。结果里模型和程序保护分开计数，见下文。

## 大家分别接哪里

- 我这边做 Agent＋RAG：理解玩家的话、追问、查规则、决定调用哪个已有功能、叙述结果。
- 做网页的同学负责 React 和 FastAPI，按 `docs/interfaces.md` 接 Python 方法。
- 做角色、骰子和保存的同学继续负责那部分。我这边调用已有代码，不另写一套。
- 故事条件和隐藏线索放在故事文件里。AI 只能看到当前允许公开的内容。

## 先怎样打开

进入 **`versions/ai-kp-v1/`**，建议用 Python 3.12，各自在自己电脑创建环境：

macOS / Linux：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-agent.txt
.venv/bin/python -m kp_agent --mode demo
```

Windows PowerShell：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-agent.txt
.\.venv\Scripts\python.exe -m kp_agent --mode demo
```

`demo` 是离线判断，不是真正大模型，骰子仍随机。
装好环境后，也可以使用本目录的 `run_demo.command`（Mac）或 `run_demo.bat`（Windows）。
Windows 还需要实际运行确认，不把 Mac 的结果当成 Windows 实测。

要用 DeepSeek，把本目录 `.env.example` 复制为 `.env`，在自己电脑填好 `DEEPSEEK_API_KEY`，
再用 `run_deepseek.command` / `run_deepseek.bat`，或：

```bash
.venv/bin/python -m kp_agent --mode deepseek --db saves/deepseek.sqlite3
```

Windows 对应命令是：

```powershell
.\.venv\Scripts\python.exe -m kp_agent --mode deepseek --db saves/deepseek.sqlite3
```

运行在线模式会产生 API 用量。密钥、虚拟环境和个人存档不用发群里，也不要提交 GitHub。
本版本用自己的存档目录；不要复制 v1 的书房存档来冒充完整故事进度。

## 这次多了什么

可以观察、调查、和 NPC 聊天、走当前已开放的出口、使用已有物品、最后结束调查。
离开一个房间不等于整局结束，按当前公开提示继续即可。

| 命令 | 看什么 |
|---|---|
| `/status` | 角色与当前进度 |
| `/inventory` | 已经拿到的物品 |
| `/clues` | 已发现线索 |
| `/map` | 现在在哪、去过哪里、当前出口 |
| `/rolls` | 已保存行动的骰子 |
| `/history` | 之前的对话 |
| `/retry` | 恢复没处理完的原消息 |
| `/review` | 整段故事结束后复盘 |
| `/restart` | 从角色初态重新开始整个故事 |
| `/quit` | 保存退出 |

每次行动自动保存，关闭后再开会接着原进度。提示只是建议，仍可自由输入。
开局绷带恢复 2 HP 是这个故事的简化设定；不是完整急救规则。
主线没有法术，不消耗 MP。复杂战斗、通用孤注一骰和任意模组自动主持还没做。

## 网页同学先看什么

看 `docs/interfaces.md` 和 `kp_agent/graph.py` 的 `KeeperService`。
除了聊天、角色和进度，现在还有查看物品、线索、已保存骰子的方法。
消息结果新增 `scene_transition` 和 `new_items`，网页可以显示场景切换和新增物品。
最终显示按 `progress` 的当前公开状态更新，不要直接读完整故事文件给玩家看。

故事在 `data/campaign.json`，旧书房调试文件保留在 `data/scenes/study_legacy.json`。
规则仍然只查 `data/agent_rules.md`，三个地点共用，不把未来剧情放进规则库。
`characters/` 继续只用已有固定角色卡，不额外放空白卡，也不要随手重存 Excel 破坏公式缓存。

## 这次实际检查到了什么

- v2 目前的 98 项离线测试全通过（原 60 项＋这次新增 38 项）。
- 这次还修了满血建议包扎、用完物品仍说持有、已整理档案仍说错乱，以及结局显示等问题。
  否定、假设和风险询问会先分清楚，避免误触行动；新行动也不会被上一条规则解释覆盖。
  这次检查没有调用付费模型，真实 DeepSeek 对这些新修改的表现尚未复测。
- 首轮 23 条自由说法，离线关键词判断答对 14 条；真实 DeepSeek 原始规划和应用侧都通过 21 条。
- 修复后只重查了 4 条，模型原始规划通过 3 条，程序加保护后通过 4 条。
  “用钥匙开站台”这句模型仍选错，是代码改成追问，不能说模型全对，也没有完整重跑那 23 条。
- 实际服务跑了 2 个回合、4 次 API，8 项结构检查通过；人工仍发现一次“30≤27”的数学说明错误。
  已改为程序调用已有引擎算成功等级，直接显示带出处的算例。
  修后用 1 次真实 API 检查了 6 项，全部通过；不再让模型重写这类算式。

此前归档的模型检查共 33 次 API 请求，没有自动重试，用户自行试玩另计。详细记录见
[泛化测试结果](docs/泛化测试结果_2026-10-21.md)。
报告同学可以看 [问题发现与修复记录](docs/问题发现与修复记录.md)，里面有原问题、原因、改法、截图及验证范围。
自由表达那组使用人工准备的进度，不是真正掷骰一路通关；后面仍要继续体验完整故事和其他说法。

成功等级讲解里的数字是“假设掷出多少”的例子，不是真骰子；讲解本身不会扣血或改角色。
其他剧情叙述继续由模型生成。本次覆盖原来的版本目录；仓库根目录、角色／骰子及数据库底层保持原样。
