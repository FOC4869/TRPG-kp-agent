# ADR-0004：单进程 JSON 游戏运行器与 SSE

状态：已接受，2026-10-24。依据：用户批准的可游玩 MVP 实施计划。

网页新局使用独立的 `kp_agent/gameplay` LangGraph 编排器，不共享 CLI 的 SQLite 连接或 active_game。FastAPI 仅适配 HTTP。原内容包保持不变，`data/runtime/` 的版本化单人配置明确绑定目录模组，规定合法事件、条件、检定、效果和素材授权。数值调用 trpg。

每局位于 `saves/<game_id>/game.json`，包含模板快照、完整历史及回合日志；原子替换、有效备份和校验和防止半写入。进程锁限制单 worker，同局 asyncio 锁串行化；创建 ID 确定性映射 game_id。已记录出目先保存、效果随后一次提交；叙述失败只重做叙述。版本或完整性不兼容明确报错，不静默回滚。

POST 行动以 SSE 返回，任务独立于订阅者运行。刷新 GET 后用同一请求 ID 恢复；不实现 token 级持久事件重放。公开投影不包含规划、条件、未来剧情或文件路径；素材按本局已揭示资产检查。游戏地址是恢复凭证，本地演示仅监听回环地址，尚不提供账号权限系统。

DeepSeek 每轮至多规划及叙述两次调用，45 秒/次、120 秒/轮，不自动重试。只执行配置事件，模型不能指定骰子或修改资源。正文真实流式输出；前端持续读流并排队播放检定与后续正文，动画不阻塞后端。

替代方案：SQLite 更适合多 worker、事务查询；首版为便于审阅游戏状态选择 JSON。升级多用户服务必须重新设计认证、跨进程锁与事务存储。
