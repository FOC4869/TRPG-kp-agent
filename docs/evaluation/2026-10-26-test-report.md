# 项目整合与测试记录

日期：2026-10-26。测试环境：macOS / Apple Silicon，Python 3.12.14，Node.js 24.22.1。

## 结果

当前可玩的“雨夜来信＋理查德”已通过 **223 项后端离线检查、61 项最终完整真实 API 流程检查和 10 项补充检查**。
前端依赖安装、lint、typecheck、build 和 4 份接口检查脚本通过。
完整通关、信息不足结局、主动撤退都已在独立测试局实际走通。

新增内容为 10 位人物及原文件中的背景、头像、初始物品，以及《岭下暗影》的内容包与 11 个公开地点名称。
人物页能显示箱中物品、酒壶容器说明、未知数量和拥有资产。
按小组当前决定，新增人物和故事只做资料展示，没有进行其游戏流程测试。
按用户后续要求，页面不显示“仅供查看”“暂未开放游玩”等标记，也不显示解释性占位文案。

使用同一套原 Agent＋RAG，没有接入队友另一套 Agent。网页现在按配置读取故事、人物与 NPC，
不再用固定人物 ID 限制初始化；实际开局名单仍由发布配置决定。

## 真实模型与 API 范围

使用本机已有配置调用 **DeepSeek 官方 API / deepseek-flash**，返回模型名同为 deepseek-flash。
完整测试通过独立的 8012 HTTP 服务发送请求，真实读取 SSE；补测通过 FastAPI HTTP 测试客户端调用同一生产路由。
没有用 mock 代替真实模型来声称 API 接入通过。

所有测试游戏写入独立目录，未把玩家真实存档作为测试输入。
随后按用户要求，明确执行了一次已有理查德存档的物品补齐：两份存档各补四件物品，修改前单独备份，原剧情、数值、回合与消息保持不变。
完整路线使用真实系统随机数；补测的站台和结局起点使用原故事定义的预置进度，检定仍为真实系统随机数。
补测观察到了实际站台受伤，随后真实调用模型完成治疗与物品消耗检查。

| 范围 | 检查内容 |
|---|---|
| 开局 | 创建、同一请求重复创建、初始人物与止血包 |
| 自由输入 | 观察、翻抽屉、听管家讲述、查档案、询问学者、使用钥匙 |
| 规则 | 失败不自动扣血、成功等级、奖惩骰、孤注一掷、规则出处 |
| 意图保护 | 否定、假设、含糊对象、询问物品用法、错误物品目标、泄露剧情请求 |
| 物品 | 放下、拾回、交给 NPC、满血不消耗、钥匙消耗与获得后续物品 |
| 检定与状态 | 侦查、DEX、图书馆使用、理智、伤害、HP 恢复、MP 不凭空消耗 |
| 场景进度 | 往返、重复调查、失败后的十分钟替代、跨地点读证据、不重复发钥匙 |
| 结局 | 请求确认、取消、完整结局、信息不足、撤退、复盘、结束后拒绝行动 |
| HTTP 与保存 | 重复请求、版本冲突、空输入、跨局隔离、只读 GET、未发现素材限制 |
| 恢复 | 明确注入一次本地叙述故障，重建服务后用真实模型恢复，不重掷、不重复提交效果 |

恢复补测中的故障是测试主动注入的，不是供应商发生了网络故障。
未对 DeepSeek 人为发送错误密钥、耗尽余额或制造限流；这些错误分类由本地保护与离线检查处理。

## 发现的问题与修复

| 问题 | 原因 | 修复和验证 |
|---|---|---|
| 页面建议调查铁柜，却说对象不一致 | 照片是已获得证据，但被当成物理操作目标 | 按证据 ID 排除引用对象；完整建议直接匹配已公布的动作；真实流程通过 |
| 玩家要再追问一次才知道系统指哪个对象 | 冲突回复只有泛泛的“请明确目标” | 直接点名对象与候选操作；保存唯一候选，下一轮答“对”会重新验证后执行；离线回归通过 |
| “听听周先生怎么说”没有交谈 | 保护逻辑把句中的“怎么…离开”当成咨询行动后果 | 识别明确针对在场 NPC 的“听听”，保留假设／否定保护；真实输入通过 |
| 点“前往地下档案室”仍要求确认目标 | 两个出口共享目的地别名，字符串匹配选中另一个门 | 完整且唯一的页面行动按其真实工具映射验证，不被别名抢走；真实流程通过 |
| 威士忌有了，酒壶不见了 | 原物品显示遗漏 container 字段 | 增加容器说明；递归保留箱中物品，未知数量不补成 1；HTTP 与浏览器检查通过 |
| 理查德个人物品仍只有止血包 | 原角色模板没有导入 Excel《人物卡》F79–F82 | 补上威士忌酒壶、打火机、香烟、怪谈手抄本；新局读取角色数据，旧局在备份后显式补齐，不补发已消耗物品；带新清单的完整 API 流程通过 |
| 奖励骰说明出现“取决于你需要高还是低” | 自由生成改写了“更好／更坏”的含义 | 基本数值示例由现有骰子工具生成：奖励取 15、惩罚取 85；直接附检索出处，不实际掷骰 |
| 结案后仍说“继续问我” | 原故事结案文案适合 CLI，网页输入此时已关闭 | 网页保留原结案结果，改为点击“查看复盘”；补测通过 |
| 理智检定的附带检索词不够精确 | 卡片技能名为“理智”，部分代码只识别 SAN | 同时识别两种名称，使用理智检定／理智损失检索词；补测通过 |
| 一次规划返回无效结构导致中断 | 首轮错误地点后的级联请求中，模型输出未通过本地结构校验 | 规划格式错误转为基于眼前公开对象的追问，不执行、不猜测、不后台重试；离线故障注入通过。其他供应商错误仍保留原请求供恢复 |

首轮测试保留了 8 个未通过检查，其中包含上述前置问题引发的后续地点错误和脚本停止，不能理解为 8 个独立产品缺陷。
修复后第一次完整重跑为 62/62；补齐理查德个人物品后，再次完整重跑为 61/61。检查数量相差 1 是随机失败触发的替代步骤数量不同。
补测第一次因测试脚本把卡片名写成 SAN 而失败，实际产品卡片名是“理智”，且当时正确扣了 2 点 SAN；修正断言后补测为 10/10。
这些失败记录全部保留，没有只留下成功数据。

## 本次验证的限制

通过这些检查不代表任意自然语言或任何 COC 模组都能可靠游玩。
其他人物和故事没有做玩法验收；完整战斗、法术、多人联机不在本版范围。
本轮未在 Windows 机器双击启动，不能把 macOS 的结果当成 Windows 已验证。
API 结果有随机性，后续模型和数据变化仍需回归；底层数值与重试保护由确定代码保障。
