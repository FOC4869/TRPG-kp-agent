# 游戏状态变化提示

2026-10-24，依据用户对“让状态变化更明显”的确认，在现有状态条修复基础上实现。现有玩法范围见[简化 MVP](simplified-mvp.md)。

## 范围与显示

在场景左下角展示本轮状态提示，不占用叙事区或改变桌面页面高度。HP／SAN／MP／幸运显示实际增减（如 HP −2），新物品／数量增减和新线索显示名称；未知数量不推测。使用现有暗色与黄铜样式，减少值突出为暖红色。

提示默认显示 8 秒，允许关闭；悬停或键盘聚焦时保留，离开后重新计时。多项变化在同一面板中显示，短视口支持内部滚动及键盘聚焦；辅助阅读只播报新增内容。采用即时呈现，无需动画或新依赖。

只比较同一游戏的前后公开状态，首次读取、刷新和已提交回合恢复不重放旧奖励。按版本去重：state.updated 与 turn.completed 的相同效果只提示一次；新版本无变化不产生提示。收到检定结果后，沿既有 SSE 显示队列同步更新状态条和提示。提示不进入对话、存档或模型上下文。

## 实施与验证

独立分支 feat/game-state-feedback；只修改前端与文档。GamePage 保存最近已显示的公开快照，state/game-changes.ts 提取差异，GameStateFeedback 负责显示与生命周期，game.css 管理布局。

先验证差异提取的初始／重复／旧版本、跨局、资源截断损失、物品数量未知和线索 ID 边界；再执行 npm ci、lint、typecheck、build 与已有 SSE 检查。通过浏览器拦截的公开状态与 SSE 夹具验证实际提示、自动消失、重复／恢复与桌面／窄屏布局；不修改真实存档、不调用付费模型。按 Design、Code、QA 视角顺序自审。

## 流程长度观察

只读检查运行配置：6 场景、35 事件，包括回退、装备、互斥路线及同一威胁的多种方法。问话、遗骸、侦查、壁画均非主线前提；进入旧隧道只要求手电，前往牢笼只要求通过碎石，结尾威胁用一次成功检定或固定 HP 代价解决。叙述约 120–240 字，当前测试失踪路线 13 回合、同行路线（含可选内容）21 回合；20–30 分钟仍是未测目标。此轮交付状态提示，后续节奏调整应先确定线索与决策的用途，不靠重复检定或增加无意义回合拖长。

## 验证结果

npm ci／lint／typecheck／build、新增 check-game-changes.mjs 和既有 SSE 检查通过。覆盖资源实际扣减、回升、零值、初读与重复／旧版本／跨局抑制、物品数量增减／未知数量和按 ID 区分已知线索。

真实浏览器使用公开 HTTP／SSE 拦截夹具：同一状态更新重复发送及完成事件只显示一组4项变化；聚焦9秒仍可见，移开后8秒消失；刷新读取已提交状态与“恢复本轮”均不重放。1440×900、1280×720、390×844的提示在场景边界内、无横向溢出，截图已目视检查，无控制台错误。自动化恢复按钮等待曾受暂停的测试时钟阻塞，恢复时钟后断言全部完成，未修改产品逻辑来规避。测试结束移除路由拦截并读取真实游戏。

Design／Code／QA自审：采用现有色彩，提示不占布局高度、不强抢焦点，网络继续按原队列读取；只使用公开状态，不引入持久化或依赖。无后端改动，未重复后端测试或调用模型；真实时长尚未验证，玩法配置本轮保持现有版本以兼容存档。
