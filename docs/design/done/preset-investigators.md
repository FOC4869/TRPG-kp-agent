# 预设调查员数据

## 已确认范围

依据用户提供的十张角色卡，保存十位调查员的结构化数据、完整背景和已裁切头像。
路径为 `backend/data/characters/<id>/character.yaml`、`background.md`、`assets/portrait.png`。
不设置角色包层或 manifest，不保存整张角色卡，不依据现有 Character 类限制数据格式。
不迁移旧 Excel、不实现加载器、HTTP、前端选择页或存档，不调用模型。

## 文件与数据约定

character.yaml 保存身份、八属性、初始资源、原卡派生值、技能、攻击、装备、现金、附件引用、可填写栏目和原卡疑点。
background.md 是外貌、特质、信念、重要之人、意义非凡之地、宝贵之物和人物经历的正文依据。
技能保存基础值，困难和极难值不重复维护；截图中的冲突括号值记入 source_issues。
疑点保留原卡所列值；不得据职业补技能，不补弹药、武器型号或工具包内容，不把宝贵之物自动授予为随身装备。
原卡未提供的数量用 null，与确知的零区分。攻击引用技能，伤害分离基础骰与 DB；互相冲突的伤害标记 needs_review。
预设数据不被本局状态覆盖，未来实例须绑定版本和快照；扫描 */character.yaml 即可枚举角色。

## 实施与验证

1. 转录一套统一字段，生成十个角色目录与背景，复制已检查的头像。
2. 补充本目录格式说明、架构归属与 memory-bank；保留现有用户改动。
3. 离线解析 YAML，检查角色数、唯一 ID、引用、八属性、技能范围、攻击技能引用、资源和图片完整性；人工逐卡核对数值、背景与装备。
4. 运行后端约定 unittest；未修改前端，不触发前端构建。无新运行时依赖。

Review：数据忠实度、结构与路径边界、使用说明；本会话顺序自查。
回退：移除新增角色数据即可；原运行入口不引用这些文件。
