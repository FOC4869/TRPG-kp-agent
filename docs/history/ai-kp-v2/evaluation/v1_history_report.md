## 原来几个问题怎么改了

1. **侦查失败后还有路走。** 书桌首次调查失败时，会明确给出“花十分钟换方法细查”的选择。这是自编书房的另一条调查路线，不重掷骰。玩家选了才扣这十分钟，重复选择不再扣时间或给线索。它不是通用的“花时间就能通过任何 COC 检定”。
2. **结束后能复盘。** 可以问“什么信息没有找到”或输入 `/review`，看到本局已找到和遗漏的线索。复盘只解释，不补发遗漏奖励，不修改角色、版本、时间和已获得线索；进行中、暂停时不能借此看秘密。
3. **“说通俗一些”能接上话。** 接着上一条规则解释改写，不再无谓地问“你要解释哪部分”。普通行动回复不主动塞一大段规则，也不能用单次掉 SAN 的结果反推整个遭遇的损失公式。
4. **错误能定位。** 每次调用带游戏、消息、行动和阶段编号；区分接口错误、JSON 格式错误、目标不合法、引用不合法。日志不保存密钥、原始提示词、原始错误正文或思考正文。
5. **重复补查正常回答。** 真实测试还发现“再细查一次”会被当成越界请求，现已改为由场景解释“已经检查过”，不再提示真人接管。

## 这次真实调用又暴露了什么

第一次重跑在补查叙述处中断：虽然请求声明了 JSON Schema，模型仍偶尔直接返回普通中文。该轮共 21 次调用，4 次在格式校验处拒绝；这也解释了为什么之前偶尔需要重试。

修复做法：

- 在提示词里明确写只允许一个 JSON 对象，并给出正确字段示例。
- 先取得完整响应，再用 Pydantic 校验；格式错仍拒绝，不把普通文字擅自包装成合法结构。
- 这样即使格式出错，也能留下已返回的 token 用量和错误位置。
- 规则解释必须引用本次检索的来源；历史里的旧引用先去掉，防止混用。

修正后重跑相似对话，再跑重复补查和真实随机游戏，最后两轮 48 次调用全部通过。

本轮测试、首次排错和两次独立格式诊断合计 **71 次真实 API 请求**；已记录用量至少 155,519 token。最早 4 次格式失败在旧解析路径丢失了用量，因此这个总量不能当作完整账单。

## 扩展检测中顺手修掉的数值问题

- SAN 小于 50 时，96–99 也应按大失败处理；现在按该遭遇最大损失结算。
- 同一理智效果重复执行会再次扣值；现用已应用记录保护，同时保留未提交行动按旧状态重放的能力。
- 多个效果中后一个无效时，之前的效果可能已经改了内存；现先验证并在副本结算。
- 负数“恢复”会倒扣 HP/SAN/MP，甚至变成负数；现不会倒扣资源。
- HP 上限 11 时，5 点伤害被错误算为重伤；现在需要达到至少 6 点。
- 日累计疯狂阈值函数对不能整除 5 的数向下取整；现取达到五分之一所需的最小整数，并明确传日初基准。
- 成长检定漏了“出目大于 95”例外，还把技能错误封顶 99；现按规则允许超过 100。
- 高 STR+SIZ 的伤害加值表不再永久卡在 +4D6。
- 某些合法 JSON 但结构损坏的检索缓存不能重建、并发保存可能抢同一临时文件；现已保护。

规则核对使用已提供的《COC7th核心规则书v1.2.1》：成长 PDF79/书内71，伤害表 PDF26/书内18，通用大失败 PDF75/书内67，理智检定 PDF133/书内125。

## 仍没做的部分，不能算已经测完

- React 页面和 FastAPI 路由尚未在这个开发副本实现，因此没有做网页或多人联调。
- 自动场景效果目前只接了 SAN。HP/MP 的底层保存、显示和恢复已测，但完整战斗、施法扣 MP、治疗等行动没有接入当前场景。
- 重大伤势的长期状态、连续多次伤害后的濒死判定、完整疯狂发作和休息换日仍需进一步实现；不能把当前单次伤害结果当成完整战斗系统。
- 真实向量服务和其他模型只做模拟接口检查。当前实际运行的是关键词检索加 DeepSeek，资料范围仍是 13 项已核对规则摘要。
- 少量叙事细节由模型表达，单轮成功不保证未来永不出现格式错误或网络失败；现在能定位原因，并用原消息重试而不重新掷骰。
