# 演示步骤

这份流程用于组员排练，会写出当前故事的关键路线；玩家网页不会直接展示这些未发现信息。
不需要为了展示其他人物或地点资料，临时改动实际可玩范围。

## 演示前

按 [README](../README.md) 启动。确保后端的 DeepSeek 配置有效，打开网页，选择雨夜来信与理查德，创建新局。
保留游戏地址，关闭页面后可以凭同一地址恢复。真实模型演示会产生 API 用量。
不要把旧的已结束存档当成新开局；也不用在演示前清空所有人的存档。

## 建议的演示顺序

| 顺序 | 操作 | 让观众看到什么 |
|---|---|---|
| 1 | 模组库、人物资料、初始物品 | 多人物资料来自数据；理查德有个人物品和故事止血包 |
| 2 | 开始理查德的调查，问“我现在 HP、SAN、MP 是多少？” | 数值来自保存状态，不靠模型编 |
| 3 | 问“侦查失败会不会自动扣血？”并展开规则依据 | RAG 与真实出处 |
| 4 | 问“困难成功怎么算？” | 确定工具生成假想算例，与真实掷骰分开 |
| 5 | 自由输入“我把纸挪开，检查抽屉有没有夹层” | Agent 将自然说法映射成调查书桌，出现真实检定卡 |
| 6 | 如果失败，明确选择花十分钟换方法细查 | 失败仍能继续，时间变化与线索真实保存 |
| 7 | 询问管家，再去旧车站 | NPC 提供照片和钥匙，满足前提后切换地点 |
| 8 | 查看铁柜编号并对照照片 | 原对象匹配问题已经回归验证 |
| 9 | 找到柜子后使用黄铜钥匙，再用通行钥匙打开铁门 | 持有、前提、正确目标、消耗与奖励 |
| 10 | 进入地下档案室，整理档案、问学者、插入铜片 | 多地点进度与机械封存，MP 不凭空变化 |
| 11 | 明确结束并确认，再看复盘 | 结局按真实调查成果判断，不再继续行动 |

书桌、铁柜、档案整理都可能失败；使用界面实际出现的替代建议，不预先假定出目。
主线不是演示真实战斗或施法的场所。

## 可插入的短演示

- 在未受伤时请求使用止血包：HP 不变、物品不被浪费。
- 放下／拾回一件个人物品：背包与当前地面物品同步变化。
- “如果检查壁炉会怎样？”：咨询不直接触发理智检定。
- “用黄铜钥匙打开站台”：不能偷偷改成打开柜子，也不消耗钥匙。
- 返回书房再回车站：进度和物品不会重置。
- 刷新游戏页面：对话、线索和出目保留，不重新开局。

站台有受伤风险，壁炉会触发理智事件；可按时间选择展示，不要求演示时一定掷出失败。

## 中断怎么处理

出现“恢复本轮”时保留原请求。不要为相同行动点多个新请求，也不要手动改存档。
重新打开原游戏地址，恢复未完成正文；已经保存的检定与效果不会重做。
正式展示不必故意断网，报告可以引用已经完成的 [恢复补测](evaluation/supplement-pass.json)。

## pre 可以解释的四点

1. 单 Agent 理解自由输入，先分清行动与问题。
2. RAG 给规则出处，工具负责数值与合法性。
3. 角色、物品和故事状态持续保存，正文失败不会造成重复结算。
4. 同一套流程可读取不同配置；当前演示的是经过验证的一位玩家、三个地点。
